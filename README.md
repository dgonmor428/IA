# UserManager — 2.º DAW
Proyecto educativo SDD, EARS y TDD con OpenCode (Plan y Build). HTML5, CSS3, JavaScript vanilla y módulos ES, manipulación nativa del DOM; sin frameworks, backend ni bundler obligatorio; localStorage y JSON; node:test y node:assert/strict; lógica independiente del DOM y almacenamiento en pruebas unitarias. Autenticación simulada cliente, manipulable; solo cuentas ficticias; Web Crypto PBKDF2 con salt aleatorio; servir por HTTP localhost.

## Preparación obligatoria: Dev Container
En el anfitrión: Docker operativo y VS Code con la extensión Dev Containers (o cliente compatible). Abrir únicamente UserManager y seleccionar `Dev Containers: Reopen in Container`. La configuración inicial suministrada usa Node.js 22, Git, GitHub CLI y puerto 8000; instala OpenCode en el directorio del usuario del contenedor al crearlo. No requiere instalar Node.js u OpenCode en el anfitrión. Se necesita acceso a los registros de imágenes y npm para la primera construcción.
En la terminal integrada **del contenedor**: comprobar `whoami`, `pwd`, `test -f /.dockerenv`, `node --version`, `npm --version`, `git --version`, `gh --version`, `opencode --version`. Si OpenCode no se encuentra, comprobar `~/.local/bin/opencode` y PATH. El alumno configura identidad Git y autentica personalmente `gh auth login` y `gh auth status`; si necesita HTTPS para Git, `gh auth setup-git`. No registrar tokens ni copiar credenciales al repositorio. Abrir OpenCode desde la raíz dentro del contenedor; comprobar permisos reales y evitar autoaccept.
La aplicación se servirá mediante HTTP desde el contenedor (puerto 8000, comando a decidir en Plan); abrir la URL de puerto reenviado en el navegador del anfitrión y usar DevTools. Todas las pruebas, incluida la regresión antes/después del merge, se ejecutan dentro del contenedor. Si no se puede abrir, detener la práctica y resolver el entorno. No usar dependencias instaladas fuera.
La carpeta .devcontainer es infraestructura docente preconfigurada, no una arquitectura de la aplicación ni una implementación. No se entregan HTML, JS, CSS ni package.json. Al reconstruir el contenedor, verificar herramientas y autenticación de nuevo. No montar el socket Docker ni ejecutar el contenedor privilegiado.

## Proceso
Primero elaborar y aprobar constitution.md y AGENTS.md desde sus plantillas; después PRD, índice, todas las specs EARS, arquitectura global, planes y tareas en main. Consolidar y publicar la línea base documental antes de programar. Después una rama por especificación, TDD, revisión independiente, pruebas locales, merge fast-forward local, push exclusivo de feature, PR revisado, merge commit remoto y sincronización. Build solicita autorización para escrituras Git/GitHub. La estructura de código se deduce en Plan, no se entrega.

`docs/DESARROLLO.md` recoge únicamente trabajo realizado; no es contexto técnico. Skills bajo demanda. No usar datos reales.
